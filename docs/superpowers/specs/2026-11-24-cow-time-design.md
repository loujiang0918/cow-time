## 1. 目标

做一个 Windows 桌面小悬浮窗，默认停在屏幕右下角，始终置顶，可以拖动。它实时显示三件事：

1. 本月已经赚到的薪资（每秒刷新）
2. 今天已经赚到的薪资（每秒刷新）
3. 距离最近一个法定节假日还有几天

月薪和每天的作息时间在悬浮窗自带的设置里填写。程序名 Cow Time，可执行文件为 `cow-time.exe`。

范围：单个用户、单台 Windows 电脑、中国法定节假日。鼠标穿透、安装包、其他地区的假期、主题与字号设置不在本次范围内。

## 2. 技术选型

| 项 | 选择 | 原因 |
|---|---|---|
| 语言与框架 | Go 1.26 + Wails v3.1.0 | 产物是单个 exe（约 11.5MB），用系统自带的 WebView2 渲染；窗口 API 完整：无边框、置顶、半透明背景、单实例、屏幕工作区 |
| 前端 | 原生 HTML / CSS / JS | 页面很小；Wails 自带运行时脚本（`/wails/runtime.js`，ES 模块），静态文件用 `go:embed` 编译进 exe，构建只需要 Go |
| 计算位置 | 全部在 Go | 薪资和假期逻辑可以用 Go 单元测试直接覆盖，前端只负责渲染 |

已从 v3.1.0 源码核实的能力：

- 窗口选项：`Frameless`、`AlwaysOnTop`、`BackgroundType`、`DisableResize`、`Windows.HiddenOnTaskbar`、`Windows.BackdropType`（需要 Windows 11 22621 或更高版本）
- 拖动：在元素上声明 CSS 变量 `--wails-draggable: drag`
- 坐标：`Position()` 和 `SetPosition(x, y)` 使用绝对坐标，单位是 DIP
- 屏幕：`Screen` 类型带有 `WorkArea`，即排除任务栏之后的区域
- 事件：`WindowDidMove`、`SystemDidWake`
- 单实例：`SingleInstanceOptions`
- 在 Windows 上构建不需要 C 编译器

构建环境：本机访问不到 Go 官方模块代理（`proxy.golang.org` 连接超时），构建和安装命令通过命令级的 `GOPROXY=https://goproxy.cn,direct` 指定镜像。

### 目录结构

```
cow-time/
├── main.go               # 创建应用与窗口，装配各部分
├── go.mod                # 固定依赖 github.com/wailsapp/wails/v3 v3.1.0
├── internal/
│   ├── workhours/        # 作息时间的解析与校验
│   ├── holiday/          # 节假日数据、工作日判断、假期倒计时、数据更新
│   │   └── data/         # 内置节假日数据：2026.json、2027.json
│   ├── salary/           # 已赚金额与计薪状态（纯函数）

│   ├── wingeo/           # 窗口位置的计算（纯函数）
```

`internal/salary` 只依赖一个「某天是否工作日」的判断函数，由 `internal/holiday` 提供，测试时可以替换。`salary` 和 `config` 依赖 `workhours`；`workhours`、`holiday`、`wingeo` 不依赖其他内部包。

## 4. 薪资计算

口径：只在工作日的工作时间内计薪，按当月实际工作日数折算。

**工作日**：周一到周五且不是法定节假日；调休上班的周末（数据中标记为上班日的周六、周日）也算工作日。

**每天计薪时段**：`[上班时间, 午休开始)` 和 `[午休结束, 下班时间)` 两段。没有午休时只有 `[上班时间, 下班时间)` 一段。

**公式**：

- 当月工作日数 = 当月自然日中工作日的个数
- 当月计薪总秒数 = 当月每一个工作日按各自作息算出的每天计薪秒数之和
- 当月秒薪 = 月薪 ÷ 当月计薪总秒数；当月计薪总秒数为 0 时秒薪记为 0
- 今日已赚 = 当月秒薪 × 今天已经计薪的秒数
- 本月已赚 = 当月秒薪 ×（本月 1 日到今天，每天已经计薪的秒数之和）

**性质**：

- 月底最后一个工作日下班时，本月已赚正好等于月薪。
- 秒薪随月份变化。月薪 10000 时，2026 年 11 月有 21 个工作日，每个工作日 476.19 元；2026 年 10 月有 18 个工作日，每个工作日 555.56 元。
- 每秒都用当前时间重新计算，不做累加，所以睡眠、关机、修改系统时间都不影响结果。
- 使用系统本地时间。

**假期数据缺失时**：如果当月所在年份的假期数据还不可用，当月的工作日先只按周一到周五统计，数据到位后自动纠正。

## 5. 假期

### 5.1 数据

- 来源：holiday-cn 公开数据集（GitHub 上的 `NateScarlet/holiday-cn`，内容整理自国务院办公厅每年发布的通知）。
- 格式：每条记录包含节日名、日期、是否放假。`isOffDay: true` 是放假日，`isOffDay: false` 是调休上班日。
- 内置 2026、2027 两年的数据，随程序一起编译。
- 本地缓存目录：`%APPDATA%\cow-time\holidays\<年份>.json`。
- 同一年同时存在缓存和内置数据时，以缓存为准。

### 5.2 自动更新

这是程序唯一的联网行为。

- 触发条件：启动时，「明年」的数据既不在缓存里也不在内置数据里，并且距离上次尝试已经超过 24 小时。
- 动作：从 `https://cdn.jsdelivr.net/gh/NateScarlet/holiday-cn@master/<年份>.json` 下载，单次超时 10 秒。失败时隔 1 秒重试，一次更新最多尝试 3 次。
- 校验：JSON 可以解析；`year` 等于请求的年份；每条 `date` 都是当年合法的 `YYYY-MM-DD` 日期。通过校验才写入缓存。
- 无论成功还是失败，都把本次尝试的时间写入配置。

超时放宽并带重试的原因：实测从本机新建连接到这个数据源时，偶尔会在 TLS 握手阶段停顿并一直等到超时，随后重试即可成功。更新在后台进行，不影响界面。

### 5.3 倒计时规则

- 周末不算假期。
- 把日历上连续的放假日合并成一个假期段。段名按顺序取段内出现过的节日名，去重后用「、」连接。
- 「最近的假期」是结束日期不早于今天的第一个假期段：
  - 今天在假期段之前：显示「距{段名} {N} 天」，N = 放假首日 − 今天，按自然日计算。
  - 今天在假期段之内：显示「{段名} 假期中，还剩 {N} 天」，N = 假期最后一天 − 今天 + 1。
  - 找不到这样的假期段：显示「假期数据待更新」。

例：2026-11-24 时，下一个假期是 2027 年的元旦（1 月 1 日至 3 日），显示「距元旦 38 天」。

## 6. 前端与 Go 的接口

Go 通过 Wails 服务向前端提供四个方法。

**`GetStatus()`**：前端每秒调用一次，返回当前时刻的全部显示数据。

```ts
interface Status {
  salaryConfigured: boolean;   // 是否已经设置月薪
  monthEarned: number;         // 本月已赚，单位元，未取整
  todayEarned: number;         // 今日已赚，单位元，未取整
  state: "working" | "beforeWork" | "lunch" | "afterWork" | "dayOff";
  dayOffReason?: "weekend" | "holiday";   // 仅 state 为 dayOff 时存在
  holiday:
    | { kind: "upcoming"; name: string; daysLeft: number }
    | { kind: "ongoing";  name: string; daysLeft: number }
    | { kind: "unknown" };
  settings: Settings;          // 当前生效的设置，设置视图用它填充表单
}
```

**`SaveSettings(settings)`**：校验并写入配置，返回是否保存成功以及失败原因。`settings` 的结构是 `{ monthlySalary: number, workHours: { start, lunchStart, lunchEnd, end }, backgroundStyle: string }`，四项时间都是 `"HH:MM"` 字符串，`backgroundStyle` 是背景风格的值。它另外带有 `weekdayHours`，结构与配置文件里相同。

**`EnterSettings()`**：把窗口切换成设置视图，窗口变高，放不下时向上移动。

**`LeaveSettings()`**：把窗口切回显示视图，恢复原来的位置和大小。

前端行为：

- 页面加载后立即调用一次 `GetStatus()`，之后每秒调用一次。
- 金额保留三位小数，加千位分隔符。小数位数由 `frontend/main.js` 里的常量 `DECIMAL_PLACES` 决定。
- 进入和离开设置视图时，前端分别调用 `EnterSettings()` 和 `LeaveSettings()`，由 Go 调整窗口的大小和位置。
- ✕ 调用窗口关闭。配置在变化时就已经写入（保存设置时、窗口停止移动后），所以退出时不需要额外保存。

## 7. 配置与窗口位置

配置文件是 `%APPDATA%\cow-time\config.json`：

```json
{
  "monthlySalary": 10000,
  "workHours": { "start": "09:00", "lunchStart": "12:00", "lunchEnd": "13:00", "end": "18:00" },
  "backgroundStyle": "aurora",
  "window": { "x": 1664, "y": 972 },
  "holidayCheckAt": "2026-11-24T16:40:00+08:00"
}
```

- `workHours.lunchStart` 和 `workHours.lunchEnd` 为空字符串时表示没有午休。
- `window` 缺失时使用默认位置。
- `backgroundStyle` 是背景风格，取值和默认值见视觉风格设计。
- 配置里还可以有一项 `weekdayHours`，记录某些星期与默认作息不同的地方，结构和规则见按星期几设置作息的设计。

窗口位置规则：

- 默认位置在主屏幕工作区的右下角，距离右边缘和下边缘各 16 DIP。
- 窗口停止移动 300 毫秒后，把窗口位置写入配置。
- 启动时恢复保存的位置。如果窗口与所有屏幕的工作区重叠出来的可见区域小于 48×32 DIP，就认为位置已经失效，回到默认位置。
- 程序已经在运行时再次启动，不会出现第二个悬浮窗，而是把已有的窗口恢复、显示并置于前面。
- 点击 ✕ 退出程序。配置在变化时立即写入，退出时不需要额外保存。

## 8. 异常处理

| 情况 | 处理 |
|---|---|
| 配置文件不存在 | 按默认值启动，进入设置视图 |
| 配置文件损坏或字段非法 | 忽略损坏的内容，按默认值启动 |
| 月薪还没有设置 | 金额显示 `--`，进入设置视图 |
| 假期数据下载失败（包括连接在握手阶段停顿）或校验不通过 | 失败后隔 1 秒重试，一次更新最多尝试 3 次；仍然失败则保持现有数据，24 小时后可以再试 |
| 当年假期数据缺失 | 工作日只按周一到周五统计；找不到假期段时显示「假期数据待更新」 |
| 保存的窗口位置在屏幕外 | 回到默认位置 |
| 重复启动 | 恢复并激活已有的窗口 |

## 9. 测试

**Go 单元测试**（表驱动）：

- `internal/workhours`：作息时间的解析与校验；每天的计薪秒数；到某一时刻为止的计薪秒数。
- `internal/salary`：当月工作日数（普通月份、含节假日、含调休上班日、当月没有工作日）；秒薪；今日与本月金额（月初、月末、周六、含节假日的月份）；计薪状态。
- `internal/holiday`：数据校验；工作日判断；假期段的合并与命名；倒计时的三种输出；内置数据的条数与关键日期；远端数据的下载与校验；缓存优先于内置数据。
- `internal/config`：默认值、读写往返、内容无效时回退到默认值、写入失败时内存里的配置保持不变。
- `internal/wingeo`：默认位置；保存的位置是否可见；设置视图的让位；窗口所在的工作区。
- `internal/service`：`GetStatus` 在给定时刻的完整输出；保存设置的校验；窗口初始位置的恢复与回退；拖动位置的保存，以及程序自己移动窗口时不保存；设置视图的让位与恢复；节假日数据更新的触发条件与重试；前端使用的服务全名与 Go 侧的包路径一致。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| Wails v3.1.0 发布时间很近，边角行为没有经过长期验证 | 实现的第一步先用最小窗口验证四件事：无边框、置顶、半透明背景、拖动。通过之后再做功能 |
| 系统的磨砂背景（亚克力）铺满整个矩形窗口，会在页面的圆角外面露出一圈长方形 | 窗口使用逐像素透明，不使用系统磨砂。代价是卡片后面的桌面内容是清晰的，没有模糊 |
| 内置的假期数据覆盖的年份过去之后，下载源不可用 | 工作日退化为只按周一到周五统计；假期一行明确提示数据待更新，不显示错误的天数 |
