# Cow Time 按星期几设置作息的设计

- 日期：2026-11-24
- 状态：已确认并实现（2026-11-24 用户确认设计，2026-11-25 实现）
- 基础版本：[Cow Time 悬浮窗设计](2026-11-24-cow-time-design.md)、[视觉风格设计](2026-11-24-visual-style-design.md)

## 1. 目标

每天的作息可以不一样。有一套默认作息，某些星期几可以单独设置。

例：周一、周二、周四 20:30 下班，周三、周五 18:00 下班。

范围：只改作息的保存方式、金额的计算和设置视图。

## 2. 设置界面

```
 设置                                        ✕
 月薪                                 [ 10000 ]
   [默认] 一  二  三  四  五 ┃ 六  日          ↺
   六、日只在调休上班时生效
 上班时间                             [ 09:00 ]
 午休开始                             [ 12:00 ]
 午休结束                             [ 13:00 ]
 下班时间                             [ 20:30 ]
 背景风格                       [素色] 极光  霓虹  星空
                                        [ 取消 ]  [ 保存 ]
```

- 设置视图多一行星期标签：「默认」加上一周七天。选中某一天之后，下面四个时间显示的就是这一天生效的作息。
- 六、日两个标签比工作日更淡，五和六之间有一条分隔线。标签下面常驻一行说明「六、日只在调休上班时生效」，选中六或日时这行说明变亮。
- 周六、周日平时不是工作日，这一点不受作息时间影响：不计薪，显示「休息日」。六、日两个标签下的时间只在调休上班时使用。
- 选中「默认」时修改的是默认作息。所有没有单独设置的星期都跟着变。
- 选中某一天时修改只影响这一天。修改之后，这一天的标签上出现一个小圆点，表示它和默认作息不同。
- 右侧的 ↺ 是「恢复默认」：删除选中这一天的单独设置，回到默认作息。它只在选中的那一天有单独设置时出现。
- 某一项改回和默认相同的值之后，这一项就不再算作单独设置。如果一个星期不再有任何不同的项，它的小圆点消失。
- 背景风格随「保存」生效的规则不变。设置视图的窗口尺寸从 240×336 DIP 变为 240×392 DIP。

## 3. 保存方式

配置里的 `workHours` 继续表示默认作息。配置里新增一项 `weekdayHours`，只记录某些星期与默认作息不同的地方：

```json
{
  "monthlySalary": 10000,
  "workHours": { "start": "09:00", "lunchStart": "12:00", "lunchEnd": "13:00", "end": "18:00" },
  "weekdayHours": {
    "1": { "end": "20:30" },
    "2": { "end": "20:30" },
    "4": { "end": "20:30" }
  },
  "backgroundStyle": "aurora"
}
```

- `weekdayHours` 的键是 `"1"` 到 `"7"`，`"1"` 是周一，`"7"` 是周日。
- 每一项里有值的字段覆盖默认作息，没有出现的字段沿用默认作息。
- 某一天生效的作息 = 默认作息套上这一天的覆盖。
- 配置里没有 `weekdayHours`，或者它是空对象时，七天都使用默认作息。

## 4. 金额计算

每天的计薪时段、工作日的判断方式都不变，变化的是各天的计薪时长可以不同。

- 当月计薪总秒数 = 当月每一个工作日按各自作息算出的每天计薪秒数之和
- 当月秒薪 = 月薪 ÷ 当月计薪总秒数；当月计薪总秒数为 0 时秒薪记为 0
- 今日已赚 = 当月秒薪 × 今天按照今天的作息已经计薪的秒数
- 本月已赚 = 当月秒薪 ×（本月 1 日到今天，每天按照各自作息已经计薪的秒数之和）
- 计薪状态（未上班、午休中、已下班等）按照今天的作息判断。

性质：

- 月底最后一个工作日下班时，本月已赚仍然正好等于月薪。
- 计薪时间长的日子，当天赚得多。
- 调休上班的周六、周日按照各自星期几的作息计算。

例：月薪 10000，默认作息 9 点上班、12 点到 13 点午休、18 点下班，周一、周二、周四 20:30 下班。2026 年 11 月有 21 个工作日，其中 13 个是下班晚的日子，每天计薪 10.5 小时；其余 8 个每天计薪 8 小时。当月计薪总秒数是 200.5 小时，秒薪约 0.013854 元。下班晚的日子每天约 138.54 元，其余每天约 105.74 元。

## 5. 校验与异常

| 情况 | 处理 |
|---|---|
| 保存时，默认作息或某一天的生效作息不合法 | 保存失败，提示「上班 < 午休开始 < 午休结束 < 下班」，原来的设置不变 |
| 配置里 `weekdayHours` 的键不是 `"1"` 到 `"7"` | 忽略这一项 |
| 配置里某一天的覆盖套上去之后作息不合法 | 忽略这一天的覆盖，这一天使用默认作息 |
| 上一行的两种情况 | 其余配置照常生效 |

## 6. 前端与 Go 的接口

- `SaveSettings(settings)` 的 `settings` 增加 `weekdayHours` 字段，结构与配置文件里相同。没有单独设置时它是空对象。
- `GetStatus()` 返回的 `settings` 里带有 `weekdayHours`，设置视图用它显示小圆点。
- `workHours` 的结构和含义不变。

## 7. 测试

**Go 单元测试**（先写测试再实现）：

- `internal/workhours`：覆盖项套用到默认作息；没有值的字段保持默认作息。
- `internal/config`：某一天生效的作息；读取配置时保留合法的覆盖、忽略不认识的键和不合法的覆盖；读写往返。
- `internal/salary`：当月计薪总秒数；各天作息不同时的秒薪、今日已赚和本月已赚；计薪状态按照当天的作息判断。
- `internal/service`：`SaveSettings` 保存合法的覆盖、拒绝不合法的覆盖；`GetStatus` 返回的 `settings` 带有 `weekdayHours`。
- `internal/wingeo`：设置视图变高之后，「向上展开」的用例仍然成立。

**前端**：

前端没有自动化测试。构建之后截图核对新增的一行，并用界面自动化走一遍：修改周一的下班时间、保存、重启之后保持、恢复默认。

## 8. 不在本次范围内

按具体日期做一次性的调整、按星期几设置是否上班、超出作息的时间算额外报酬、多套作息之间切换。
